# المواقع وتوزيع المخزون

المسار الأساسي `/api/v1/storage-locations`. المصادقة والصلاحيات الحالية إلزامية. كل كتابة تجارية تُرفض أثناء جرد نشط بـ409 و`code: STOCKTAKE_ACTIVE`، حتى للمدير. لا Flutter ضمن هذه المرحلة.

## الصفوف والأرفف

| المسار | الدور | الطلب/السلوك |
| --- | --- | --- |
| POST `/rows` | ADMIN | `{code,name}`؛ رمز ثابت فريد داخل MAIN، 201 |
| POST `/shelves` | ADMIN | `{rowId,merchantId,code,name}`؛ صف وتاجر نشطان، 201 |
| PATCH `/rows/:id` أو `/shelves/:id` | ADMIN | `name` و/أو `isActive` مع reason إلزامي؛ لا تغيير ملكية أو رمز أو صف أو حذف تاريخي |
| GET `/rows` و`/shelves` | فريق المخزن؛ والتاجر بملكيته | قراءة مرقمة؛ التاجر يرى صفوف أرففه وأرففه فقط |
| GET `/balances` | الأدوار الأربعة | أرصدة المواقع المتاحة؛ `shelfId:null` يعني كمية غير موزعة |
| GET `/custody` | الأدوار الأربعة | عهدة المرتجع حسب مصدر الاستلام والموقع، منفصلة عن المتاح |
| GET `/entries` | الأدوار الأربعة | دفتر توزيع ثابت: المصدر والكمية الموقعة والمنفذ ووقت الخادم |
| GET `/transfers` | الأدوار الأربعة | مستندات النقل الداخلي وسببها والمنفذ ووقتها |

كل مسار يقبل فلاتره المدعومة فقط، بالإضافة إلى `page=1` و`limit=50` بحد أقصى100:

| قراءة GET | الفلاتر المدعومة |
| --- | --- |
| `/rows` | `merchantId,rowId` |
| `/shelves` | `merchantId,rowId,shelfId` |
| `/balances` و`/custody` | `merchantId,rowId,shelfId,itemId` |
| `/entries` و`/transfers` | `merchantId,shelfId,itemId` |

أي فلتر غير مدعوم يرجع400 بدل تجاهله. تغيير توافق مهم: `itemId/shelfId` في `/rows`، و`itemId` في `/shelves`، و`rowId` في `/entries` أو `/transfers` كانت تقبل بلا أثر، وأصبحت مرفوضة. لا يُسمح للتاجر بطلب merchantId مختلف. سجل النقل لا يكشف بيانات تاجر آخر.

PATCH المواقع يسمح بحذف `name` أو `isActive` من الطلب، لكن لا يسمح بقيمة `null` لأي منهما. الطلب الفارغ أو الاسم الفارغ أو حقول تغيير الملكية/الرمز ترجع400 دون تغيير البيانات. `false` قيمة Boolean صحيحة للتعطيل، مع استمرار شرط خلو الموقع من المخزون والعهدة.

كل رف يتبع تاجرًا واحدًا، والتاجر قد يمتلك أرففًا في عدة صفوف. رمز الموقع أحرف لاتينية كبيرة/أرقام/`_`/`-` من1 إلى40. التعطيل يُرفض إذا وجد مخزون أو عهدة في الرف أو داخل الصف. نقل الملكية أو الحذف ليس endpoint مدعومًا.

## التوزيع داخل عمليات المخزون

العمليات الناجحة الجديدة تحتاج توزيعًا كاملًا على أرفف نشطة تخص تاجر الصنف:

```json
{"placements":[{"shelfId":"UUID","quantity":3},{"shelfId":"UUID","quantity":2}]}
```

- كل بند استلام أول: `placements` مجموعها يساوي كمية البند.
- الخروج: `placements` قائمة `{itemId,shelfId,quantity}`؛ تغطي كل بنود الشحنة بالكامل. التسجيل والتجهيز لا يحجزان مخزونًا.
- التسوية اليدوية: `placements` مقدارها يساوي كمية التسوية، والسحب يتحقق من رصيد الرف؛ ADMIN فقط.
- كل بند استلام مرتجع: `placements` تسجل موقع العهدة، دون زيادة المتاح.
- مجموعة GOOD بالفحص، أو `ACCEPT_TO_STOCK`: `placements` لأرفف المتاح و`custodySources` بنفس شكلها لتحديد مواقع سحب العهدة. عند حذف custodySources تستخدم نفس placements كمصدر عهدة؛ إن تغير موقع الإضافة يجب تحديد المصدر صراحة.
- مجموعات NOTED بالفحص والقرارات المرفوضة لا تقبل حقول توزيع المتاح؛ تبقى عهدة حتى معالجة أخرى معتمدة.

تُرفض الأرفف المكررة ضمن توزيع حركة واحدة، أو ملكية خاطئة، أو توزيع ناقص/زائد، أو كمية سحب تتجاوز رصيد الموقع. UUID وحروفها وترتيب توزيعاتها تُطبّع عند حساب هوية إعادة الطلب. المعاملة تثبت المستند والدفتر والإجمالي والتوزيع والعهدة معًا، والفشل يرجع الجميع.

قاعدة البيانات تنشئ إدخالًا مؤقتًا غير موزع للحركة ثم يعيد API توزيعه داخل نفس المعاملة. الإدخال وعكسه جزءان ثابتان من **نفس حركة المخزن**، ولا يمثلان استلامًا أو تسوية إضافيين. لا تفسر كل إدخال موقع كحركة زيادة مستقلة؛ استخدم المصدر والكمية الموقعة. عند commit يساوي مجموع أرصدة المواقع الرصيد الإجمالي ودفتر المخزن.

## النقل الداخلي والتهيئة

POST `/transfers`، ADMIN أو WAREHOUSE_KEEPER، مع `Idempotency-Key` UUIDv4:

```json
{"itemId":"UUID","fromShelfId":"UUID","toShelfId":"UUID","quantity":2,"reason":"نقل القطع إلى رف إضافي للتاجر"}
```

يحفظ المستند طرفي النقل والمنفذ واسمه وقت العملية ووقته وسببه؛ رصيد المخزن لا يتغير ولا تنشأ تسوية. إعادة نفس المفتاح من نفس الفاعل وبنفس الطلب ترجع المستند نفسه، مع `replayed:true`. الرد201 به `{replayed,transfer}` في الحالتين. تغيير الطلب أو الفاعل لنفس المفتاح409.

`fromShelfId:null` أو حذفه يعني توزيع كمية غير موزعة؛ **ADMIN فقط**. الترحيل لا يخترع رفًا ولا حركة افتتاحية؛ يحفظ الكمية القديمة في مجموعة غير موزعة ويضيف سجل BASELINE للمواقع فقط. يجب توزيع كل كميات المخزون والعهدة القائمة قبل فتح الجرد.

POST `/custody-transfers`: نفس الأدوار وإعادة الطلب، مع `{receiptLineId,fromShelfId,toShelfId,quantity,reason}`. ينقل عهدة **نفس بند استلام المرتجع** دون تغيير المتاح أو سقف المرتجعات. توزيع العهدة غير الموزعة للمدير فقط. لا تحويل بين SKU أو تجار أو مصادر مرتجعات مختلفة.

سجل العهدة يحفظ المصدر والموقع والمنفذ والوقت. ما زال تصحيح عجز عهدة المرتجعات أو إخراجها النهائي مسارًا مستقلاً غير منفذ؛ لا يمكن استخدام تسوية المخزون المتاح لإخفائه.

## عقد OpenAPI — تحديث 2026-10-09

Swagger يعلن DTO الاستجابة للصف/الرف والأرصدة والعهدة والدفتر والنقل، وحقول pagination، وUUID ووقت الخادم بصيغة date-time، والحقول nullable القائمة فعليًا مثل shelfId غير الموزع. Idempotency-Key مطلوب في عمليتي النقل فقط؛ الإنشاء/تعديل المواقع والقراءة لا يحتاجانه. النقل يظل201 في الإنشاء والإعادة مع `{replayed,transfer}`. النماذج تصف JSON الفعلي ولا تغير الاستجابة أو قواعد المخزون.

هذه مرحلة الباك إند وحده؛ Flutter مرجع للقواعد والمتطلبات، واستبدال اتصاله بالباك إند الجديد مرحلة لاحقة مستقلة.


## سجل تدقيق المواقع — 2026-10-09

PATCH rows/shelves يتطلب reason نصًا بين10 و2000 حرف بعد trim، مع حقل name
أو isActive واحد على الأقل. الإنشاء والتحديث والحالة تحفظ قبل/بعد مع الفاعل
والوقت داخل المعاملة. لقطة before تقرأ بعد قفل الصف لمنع سجل حالة قديمة
عند التزامن. التغيير لا ينقل قطعًا أو يغير ملكية رف. راجع
[audit-events-api.md](audit-events-api.md) لعقد القراءة ADMIN فقط.

### حالة حروف UUID في نطاق القراءة

فلتر `merchantId` الصحيح يقبل الحروف الصغيرة والكبيرة والمختلطة للهوية نفسها.
الخدمة تطبع الفلتر قبل مقارنة ملكية التاجر؛ هوية تاجر آخر تظل403، والتفاصيل
الأجنبية تظل404. غياب الفلتر يبقي نطاق جلسة التاجر؛ الأدوار الداخلية تحتفظ
بصلاحية القراءة عبر التجار. UUID غير صالح أو فلتر متعدد القيم يرجع400.
