# ماذا بعد استكمال السكيما؟

السكيما تحدد شكل البيانات والعلاقات والأنواع. خدمات الباك إند تحدد من يحق
له تنفيذ العملية، وشروطها، وترتيب خطواتها، ومعاملتها وتأثيرها في الدفاتر.
SQL constraints/triggers تحمي ثوابت البيانات في قاعدة البيانات. DTO/controller
يحددان عقد API والتحقق؛ الاختبارات تثبت السلوك الفعلي.

في Stocked بدأ تنفيذ اللوجيك مع كل جزء من السكيما بالفعل: مصادقة وجلسات
وإدارة؛ أصناف وتسلسل أكواد؛ استلام يزيد الرصيد؛ خروج شحنة يخصمه؛ فحص وقرار
مرتجع؛ جرد يقفل الكتابة وتسويات ADMIN؛ وسجل تعديل ذري دائم. هذه خدمات
TypeScript ومعاملات Prisma وقيود SQL واختبارات، لا جداول تنتظر كتابة لوجيكها.
مثال موجود: receipt10 → shortage1 → shipment4 → returnGOOD1 + acceptedNOTED3
→ stocktake shortage1، برصيد8، ومصادر كل حركة محفوظة ومختبرة.

## تسلسل الاستكمال

1. **إغلاق نواقص العمل والعقود المثبتة:** تحديد ما يحتاج قرار عمل مستقل مثل
   تصحيح استلام مرتجع بكمية خاطئة، وتسوية عجز عهدة المرتجعات أو إخراجها
   النهائي. الدفاتر الحالية لا تسمح بحذف التاريخ لإخفاء الخطأ. لا نخترع
   هذه السياسات أو نعدل الكميات قبل اعتماد مخططها. UUID القراءة والبيئة
   المحلية أُغلقت في نطاق الصيانة المعتمد؛ راجع قسم22 من ملف التقدم.
2. **قبول دورة أعمال كاملة:** سيناريوهات العميل ودور كل مستخدم، الإعادة،
   التزامن، آخر مدير، تعطيل التجار، ملكية القراءة، الجرد والاعتماد، والرصيد
   والمصادر. نراجع الحالات الناقصة بالعقود والمصدر والاختبارات، لا بعدد الجداول.
3. **تجهيز التشغيل:** أدوار DB runtime/migrations وgrants، TLS والأسرار،
   dependency review، backups دورية واختبار restore، monitoring وتشخيص
   الأعطال. نجاح الاختبارات المحلية أو backup archive لا يثبت جاهزية إنتاج.
4. **staging وتجربة قبول:** نشر مضبوط بقرار مستقل، migrations واختبار اتصال
   وطلبات فعلية وبيانات تجريبية معزولة، دون تحويل قاعدة التطوير إلى إنتاج.
5. **ربط العميل:** بعد ثبات العقود وربط جلسة المصادقة والصلاحيات والأخطاء،
   يحوّل Flutter لاحقًا من الباك إند القديم إلى API الجديد. لا تعديلات Flutter
   في دفعات الباك إند الحالية. عميل الويب يحتاج سياسة cookies/CSRF/CORS محددة
   إذا اعتمد؛ لا تضاف افتراضيًا بلا عميل مقصود.
6. **الإطلاق والمتابعة:** تشغيل ترحيلات موثقة وbackup/restore ومراقبة وسجل
   release، ومعالجة المشكلات المثبتة دون تعديل الدفاتر التاريخية مباشرة.

السكيما يمكن أن تتطور إذا ظهرت قاعدة أعمال جديدة معتمدة؛ استكمالها لا يعني
أن نعيد كتابة اللوجيك الموجود، ولا يعني اكتمال كل سياسات المشروع أو الإنتاج.
هذا roadmap لتفسير العمل المتبقي، وليس اعتمادًا لتنفيذ كل المراحل مرة واحدة.
