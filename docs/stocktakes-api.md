# عقد الجرد وقفل النظام

المسار الأساسي `/api/v1/stocktakes`. الأنواع: `FULL / MERCHANT / ROW / SHELF`. جميع أرفف التاجر تدخل في MERCHANT؛ جميع أرفف الصف تدخل في ROW. المخزن الحالي MAIN. يمكن فتح دورة نشطة واحدة فقط، وأي نطاق جزئي يقفل النظام كله.

## دورة التشغيل

```text
COUNTING → PENDING_APPROVAL → APPROVED
                ↓ المدير يعيد العد
             COUNTING
COUNTING أو PENDING_APPROVAL → CANCELLED بواسطة المدير
```

كل POST يحتاج `Idempotency-Key` UUIDv4. الرد200 `{replayed,event}`. `event` يحفظ `stocktakeId` و`sequence` ونوع الإجراء والفاعل واسمه وقت الإجراء و`recordedAt` وتفاصيله. إعادة نفس الطلب والفاعل والمفتاح تعيد نفس الحدث حتى بعد إغلاق الدورة، ولا تعيد تنفيذ أثره. تغيير الطلب/المسار/الفاعل لنفس المفتاح409. لا يختلط replay بإجراء جديد على دورة مغلقة.

| POST | الصلاحية | الطلب |
| --- | --- | --- |
| `/stocktakes` | ADMIN أو WAREHOUSE_KEEPER | فتح النطاق وتسجيل المدير والحاضرين والملاحظات |
| `/:id/counts` | ADMIN أو الأمين الحاضر | عد أو إعادة عد لبند، أو إضافة صنف معروف في رف داخل النطاق |
| `/:id/attendance` | ADMIN أو الأمين الحاضر | `{userId,present,notes}`؛ حضور الموظفين يوثق ولا يمنحهم صلاحية العد |
| `/:id/notes` | ADMIN أو الأمين الحاضر | `{notes}`؛ ملاحظة إضافية أثناء العد أو انتظار الاعتماد |
| `/:id/submit` | ADMIN أو الأمين الحاضر | `{notes}`؛ يشترط عد كل بند صراحة |
| `/:id/reopen` | ADMIN | `{notes}`؛ إعادة انتظار الاعتماد إلى العد دون فك القفل |
| `/:id/approve` | ADMIN الحاضر | `{notes,confirmAttendance:true}`؛ مراجعة نهائية وتسويات وإغلاق |
| `/:id/cancel` | ADMIN | `{notes}`؛ إلغاء بسبب موثق دون تغيير أرصدة |

كل notes ختامية/إدارية من10 إلى2000 حرف. أوقات الأعمال من قاعدة البيانات؛ العميل لا يرسل فاعلاً أو وقتًا. تسجيل المدير كحاضر إقرار بشري، وليس إثبات موقع من الجهاز؛ الاعتماد النهائي يحتاج إقراره وصلاحيته وجلسة سارية.

## الفتح

```json
{"kind":"MERCHANT","targetId":"UUID","directorId":"UUID","participantIds":["UUID","UUID"],"notes":"حضور المدير والأمين لإجراء جرد التاجر"}
```

FULL لا يقبل targetId؛ باقي الأنواع تتطلبه. participantIds قائمة موظفين نشطين، تشمل فاتح الجرد والمدير المحدد، والمدير ADMIN نشط. المدير أو الأمين المسجل حاضرًا يستطيع العد. لا تُضاف صلاحية عد للموظف أو التاجر.

من أول **commit ناجح للفتح**: تُمنع كل التعديلات التشغيلية والإدارية، حتى للمدير. الفتح ينتظر إنهاء معاملات الكتابة السابقة قبل التقاط اللقطة. الطلب الذي بدأ قبل الفتح وانتظر ثم دخل بعده يُرفض؛ لا يعمل تلقائيًا بعد الإغلاق.

تثبت قائمة المواقع والتجار وأكوادهم وأسمائهم وقت الفتح. المتاح يُلتقط لكل صنف/رف، والعهدة لكل بند مرتجع/رف في فئة CUSTODY مستقلة. الأصناف غير النشطة ذات الرصيد تدخل العد. الرفوف الفارغة تدخل النطاق أيضًا ويمكن إضافة صنف معروف بكمية دفترية صفر. وجود كميات غير موزعة يمنع فتح أي جرد حتى يوزعها المدير.

## العد وإعادة العد

```json
{"lineId":"UUID","expectedVersion":0,"quantity":3,"reason":"قطعتان ناقصتان بعد مراجعة الرف","notes":"راجع الأمين الموقع كاملًا"}
```

لإضافة صنف معروف إلى موقع داخل النطاق استبدل lineId بـ`itemId` و`shelfId`. لا تجمعهما مع lineId. الصنف يجب أن يتبع تاجر الرف؛ لا ينشئ الجرد صنفًا مجهولًا. `expectedVersion` يمنع الكتابة فوق عد أحدث؛ conflict409 يتطلب تحديث العرض. كل إعادة عد تضيف سجلًا ثابتًا بهوية ووقت جديدين؛ لا تمحو العد السابق.

quantity عدد صحيح من0 إلى2147483647. **الصفر عد صالح؛ عدم العد ليس صفرًا**. reason من10 إلى2000 حرف إلزامي لكل فرق عن expectedQuantity، بما فيه فرق العهدة. الفرق = quantity - expectedQuantity. عند PENDING_APPROVAL لا يتغير العد إلا بعد إعادة المدير الدورة إلى COUNTING.

## الاعتماد والإلغاء

المدير الحاضر فقط يعتمد؛ مجرد انتهاء العد لا يفك القفل. يجري الاعتماد في معاملة واحدة:

1. إعادة التحقق من الجلسة والدور والحضور والعد النهائي.
2. إنشاء تسوية لكل فرق AVAILABLE، مصدرها stocktakeLineId، بسبب آخر عد وهوية المدير ووقت اعتماده.
3. إنشاء حركة ADJUSTMENT_IN أو ADJUSTMENT_OUT وتحديث رصيد الرف والإجمالي.
4. إغلاق APPROVED وتثبيت الملاحظات النهائية وحدث الاعتماد؛ القفل ينتهي مع commit نفسه.

الفرق صفر لا ينشئ حركة. نقصان رف وزيادة رف آخر يبقيان تسويتين مستقلتين حتى إذا صافي الصنف صفر. يحسب الإجمالي من صافي الفروق، ويظل متطابقًا مع الدفتر. كل تسوية لها وقت اعتمادها؛ دفتر المصدر واللقطة والعد لا يعدلون.

فروق CUSTODY تحفظ للمتابعة والملاحظات ولا تزيد أو تنقص المتاح. السلعة MISMATCH تبقى على مصدر عهدتها الموثق، ولا تتحول إلى زيادة SKU المتوقع. معالجة فروق العهدة منفصلة وغير منفذة بهذه المرحلة.

فشل أي تسوية أو قيد يرجع العملية كلها ويترك الدورة PENDING_APPROVAL والقفل قائمًا. لا اعتماد جزئي. الاعتماد والإلغاء المتزامنان لا ينجحان معًا. انقطاع التطبيق أو الشبكة لا يفك القفل لأن الحالة محفوظة في PostgreSQL.

إذا احتاج المدير تعديلًا آخر أثناء الجرد يلغي الدورة بسبب موثق، ويحفظ كل العد والملاحظات والحضور، دون أي تسوية أو تغيير رصيد. بعدها تُفتح العمليات. الملغى لا يستأنف؛ جرد جديد يلتقط لقطة جديدة.

## العرض فقط

القراءة حسب الصلاحية مستمرة. يُمنع الاستلام والتسجيل والتجهيز والخروج وكل مراحل المرتجعات والتسويات والنقل وإدارة المواقع والأصناف والتجار والحسابات. الخطأ409 يحتوي `code: STOCKTAKE_ACTIVE` وstocktakeId.

الاستثناء الأمني المعتمد: الدخول والخروج وتغيير كلمة المرور الذاتية وتحديث نشاط الجلسة وعدادات الحماية والسجل الأمني. إدارة الحسابات للمدير تبقى مقفلة. لا تنفيذ bootstrap أو migrations أو صيانة أعمال تتجاوز القفل.

GET `/stocktakes` يدعم status/merchantId/page/limit. GET `/:id` يعرض رأس المستند؛ GET `/:id/scopes` و`/:id/lines` مرقمان بحد100. lines تدعم merchantId/shelfId وتعرض الكمية الدفترية وآخر عد والفرق والسبب؛ المراجعات السابقة تبقى في السجلات الثابتة. GET `/:id/events` يعرض التسلسل الزمني لفريق المخزن فقط.

التاجر يرى الدورات ذات النطاق الذي يشمله وبنوده ومواقعه فقط، ولا يحصل على سجل الموظفين والحضور أو الملاحظات الإدارية العامة. طلب دورة لا تشمل التاجر404؛ طلب merchantId آخر403. الموظف للقراءة فقط.

## الأقفال والتحقق

القفل المشترك القصير لمعاملات الكتابة والعد، والحصري للفتح/المراجعة/الاعتماد/الإلغاء، على هوية واحدة قبل أقفال المستخدم والمستند والأرصدة. لا معاملة مفتوحة طوال مدة الجرد. خدمات API تفحص الحالة بعد الانتظار، وSQL يحمي الكتابات ومصادر التسويات والإسقاطات والسجل الثابت. استثناء SQL داخل الاعتماد مقيد بالمصدر المرتبط بدورة الجرد، ولا يفتح التسويات اليدوية أثناءها.

المرجع الرسمي المستخدم للتحقق من سلوك الأقفال: [PostgreSQL 17 advisory locks](https://www.postgresql.org/docs/17/explicit-locking.html#ADVISORY-LOCKS)، [functions](https://www.postgresql.org/docs/17/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS).


## عقد OpenAPI — تحديث 2026-10-09

جميع أوامر POST للجرد تعلن Idempotency-Key مطلوبًا، والاستجابة200 `{replayed,event}`، وتشمل event sequence/source/actor/server-time/details وهوية الطلب القائمة فعليًا. نماذج الرد تصف المعروض بالفعل ولا تضيف حقولًا إلى JSON.

قراءة دورة أو قائمة أو بنود تعلن عبر anyOf تمثيل الموظفين وتمثيل التاجر. رأس الدورة للتاجر يحتوي id/kind/status/openedAt/closedAt فقط؛ البنود محددة بملكيته ولا تعرض countedById/countedByNameSnapshot/countedAt. السجل events محصور بفريق المخزن. نماذج scopes/events والـ pagination والحقول nullable موثقة؛ null للكمية يدل على عدم تسجيل العد، وليس صفرًا.

anyOf مستخدم لأن التمثيل المختصر للتاجر جزء من التمثيل الكامل، دون إضافة discriminator أو تغيير شكل الرد. اختبار العقد يقارن الحقول المنشورة بالـ JSON الحقيقي لكل دور، قبل العد وبعد الاعتماد، ويتحقق من منع بيانات الموظفين عن التاجر. لا تغيير حالات HTTP أو أدوار أو تسويات في هذه المرحلة. Flutter غير معدل؛ التحويل إلى هذا الباك إند يتم لاحقًا.


## فلاتر قراءات الجرد — تحديث عقود القراءة 2026-10-09

كل قراءة لها query DTO محدد، ويقبل `page=1` و`limit=50` حتى100 بالإضافة إلى الآتي:

| GET | الفلاتر المنفذة والمقبولة |
| --- | --- |
| `/stocktakes` | `merchantId,status` |
| `/stocktakes/:id/lines` | `merchantId,shelfId` |
| `/stocktakes/:id/scopes` | `merchantId` |
| `/stocktakes/:id/events` | pagination فقط؛ موظفو المخزن دون التاجر |

أثر توافق صريح: status في lines/scopes، وstatus/merchantId في events كانت تقبل بلا أثر، وأصبحت400. الفلاتر المدعومة لم تلغ ولم تضف قواعد تصفية جديدة. merchantId الأجنبي يظل403 للتاجر، والأحداث غير متاحة له حتى بدون فلتر. Swagger ينشر query المتطابق مع المصدر الفعلي لكل مسار.

### حالة حروف UUID في نطاق القراءة

فلتر `merchantId` الصحيح يقبل الحروف الصغيرة والكبيرة والمختلطة للهوية نفسها.
الخدمة تطبع الفلتر قبل مقارنة ملكية التاجر؛ هوية تاجر آخر تظل403، والتفاصيل
الأجنبية تظل404. غياب الفلتر يبقي نطاق جلسة التاجر؛ الأدوار الداخلية تحتفظ
بصلاحية القراءة عبر التجار. UUID غير صالح أو فلتر متعدد القيم يرجع400.
