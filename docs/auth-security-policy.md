# سياسة أمان تسجيل الدخول والإدارة

**الحالة:** سياسة مرجعية؛ تنفيذ المصادقة الأساسية موثق في auth-api.md، وقواعد الإدارة منفذة في admin-api.md؛ تكامل الويب مراحل لاحقة.
**النطاق:** نظام جديد بدون Firebase؛ endpoints الدخول والجلسة وتغيير كلمة المرور والخروج منفذة. إدارة الحسابات والتجار وحماية آخر مدير منفذة؛ Cookie/CSRF لم تنفذ بعد.

## 1. الفصل بين الشيما وخدمة تسجيل الدخول

| مكان القاعدة | مسؤوليتها |
|---|---|
| Prisma / SQL migration | البريد الفريد والمطبّع، العلاقة الصحيحة للتاجر، مفاتيح خارجية، تجزئة جلسة فريدة، ترتيب الأوقات، رمز تاجر ثابت |
| Authentication Service | التحقق من كلمة المرور، إنشاء/تدوير/إبطال الجلسات، انتهاء مطلق وخمول، فرض تغيير كلمة المرور |
| Authorization / Repository | دور فعّال ونطاق بيانات التاجر لكل طلب؛ لا ثقة في role أو merchantId من العميل |
| DTO / HTTP | validation، اختيار حقول استجابة مسموحة، Cookies/CSRF/حدود الطلبات |
| التشغيل | TLS، حماية الأسرار، rate limits مشتركة بين النسخ، سجل أمني وتحديثات اعتماديات |

وجود password_hash وexpires_at لا يفعّل هذه السياسات. قاعدة البيانات لا تعرف أن requester مدير؛ ذلك فحص خدمة موثوق ضمن المعاملة.

## 2. الحساب وكلمة المرور

- لا تسجيل ذاتي أو كلمات مرور افتراضية منشورة. مدير النظام ينشئ الحسابات.
- أول مدير بإجراء تهيئة لمرة واحدة، وليس seed لكل تشغيل. NULL للمنشئ لا يمنح حسابًا جديدًا صلاحية تأسيس.
- كل بريد يُطبّع إلى lowercase مع trim قبل التخزين والدخول. التحقق من شكله في DTO والخدمة.
- Argon2id لتجزئة كلمات المرور؛ لا plaintext ولا SHA-256 لكلمات المرور. حد أدنى مرجعي: 19 MiB ذاكرة، دورتان، parallelism=1 مع قياس الأداء وتحديثه عند التنفيذ.
- طول كلمة مرور مقترح 15–128 محرفًا، يدعم Unicode دون trim أو اقتطاع كلمة المرور؛ منع الشائعة والمكشوفة. يعتمد ذلك في بلوبرنت الهوية قبل الكود.
- mustChangePassword يقيّد الجلسة إلى تغيير كلمة المرور والخروج؛ لا وصول لباقي API حتى الإكمال.
- إعادة تعيين/تفعيل برمز عشوائي أحادي الاستخدام قصير العمر محفوظ كdigest؛ جدول مستقل يصمم قبل التنفيذ، وليس عمود token داخل users.
- إعادة التعيين وتغيير كلمة المرور تبطل الجلسات وفق السياسة المعتمدة؛ منع تغيير دور أو تعطيل آخر مدير داخل معاملة وقفل يحمي من التزامن.

## 3. الجلسات

- رمز opaque من 32 بايت crypto random؛ يُحفظ SHA-256 hex فقط في sessions. الرمز الأصلي لا يظهر في URL أو logs.
- id للجلسة ليس رمز الدخول. لا roles أو merchantId منسوخة داخل الجلسة.
- الفحص في كل طلب: digest صحيح، غير مبطلة، لم تتجاوز expiresAt، خمول أقل من 30 دقيقة، حساب فعّال، وتاجر فعّال للحساب التجاري.
- expiresAt بعد 12 ساعة بحد أقصى؛ تحديث lastSeenAt لا يمد الانتهاء المطلق. هذه إعدادات مقترحة من خارطة الطريق وليست قيود SQL للمدة.
- تعطيل مستخدم أو تغيير دوره يبطل جلساته ذريًا؛ تعطيل التاجر يمنع كل حساباته حتى لو بقيت session rows.
- تدوير الرمز بعد الدخول وتغيير الامتيازات؛ لا session fixation. الخروج يبطل الجلسة على الخادم.
- للويب: HttpOnly وSecure وSameSite وسياسة CSRF لعمليات الكتابة. للعميل الأصلي: مخزن نظام آمن؛ لا حفظ رمز دخول في تخزين نصي عادي.

## 4. محاولات الدخول والصلاحيات

- رسالة عامة للدخول الفاشل، دون كشف البريد الموجود أو الحساب المعطل. مقارنة hash وهمي عند البريد غير الموجود لتقليل تمييز التوقيت.
- rate limit حسب الحساب ومصدر الطلب، مع تأخير متدرج وحدود تشغيل محددة في بلوبرنت الهوية؛ لا قفل دائم يسهل إساءة تعطيل الحسابات.
- الوسائل السابقة لا تمنح حماية brute-force بمجرد وجود الجداول؛ الاختبار يلزم بعد التنفيذ.
- رفض افتراضي للصلاحيات غير المعروفة؛ كل endpoint يفحص العملية وكل repository query يفرض ملكية السجل.
- لا قبول actorId أو serverTime أو role من DTO حركة. لا نشر passwordHash أو tokenHash حتى لحساب المدير.
- مدير النظام وأمين المخزن يراجعان المرتجعات؛ الموظف يسجل ويفحص؛ التاجر قراءة بياناته فقط.

## 5. سجل وفحوص قبل النشر

- تسجيل نجاح/فشل الدخول والتعطيل وتغيير الدور وإعادة التعيين دون كلمات مرور أو رموز أو رابط قاعدة.
- اختبار إبطال فعلي بعد التعطيل، انتهاء وخمول، منع جلسة محدود تغيير كلمة المرور من الوصول للمخزون، ومنع حساب تاجر من قراءة حساب آخر.
- اختبارات متزامنة لآخر مدير ولتعطيل مستخدم أثناء طلب مخوّل، وخطة CSRF والكوكيز وتدوير الرموز.
- صلاحيات DB runtime محدودة وmigration منفصلة؛ حساب stocked_dev الحالي حساب تطوير وليس إعداد أمان إنتاج.
- الثغرات السابقة في اعتماديات Prisma لم تُحل بهذه المرحلة؛ ممنوع اعتبار التطبيق جاهزًا للإنتاج بسبب نجاح migration.

## حالة التنفيذ — 2026-10-09

نفذ Argon2id وسياسة 15–128 محرفًا والقائمة المحلية للكلمات الشائعة، وbootstrap آمن، وجلسات opaque وانتهاء/خمول وتدوير وإبطال عند تغيير كلمة المرور، وحراس الدور والرفض الافتراضي وتحديد محاولات مشترك.
me متاح للجلسة المقيدة حتى يعرض ضرورة تغيير كلمة المرور؛ بيانات الأعمال غير متاحة لها.
القائمة المحلية لا تغطي كل كلمة مرور مسربة. إدارة الدور والتعطيل وحماية آخر مدير نفذت واختبرت في مرحلة الإدارة. إعادة التعيين وCookie/CSRF وعزل سجلات المخزون تنتظر ميزاتها؛ لا يعتبر هذا المستند إثبات تنفيذها.
انظر [عقد API وحدوده](auth-api.md) للنتائج والتعليمات الحالية.

## تحديث إدارة الهوية

الإنشاء والتعديل والتعطيل ADMIN فقط، وتراجع الجلسة والدور بعد قفل المعاملة. تغيير البريد/الدور/ارتباط التاجر وتعطيل المستخدم أو التاجر يبطل الجلسات المناسبة ذريًا. آخر ADMIN فعّال محمي حتى تحت التزامن. العقد والاختبارات موثقة في [admin-api.md](admin-api.md).
